# Design decisions

One line per decision. Newest at the bottom.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-10 | Replay answers per request: the recording is split into segments at value-changing writes, each segment has a FIFO queue per request key, and recorded response bytes are sent as-is (only TID and unit are rewritten). | Deterministic and byte-exact like VCR-style FIFO, but extra polling before a write can never return post-write values; a wall-clock state model would be flaky in CI. |
| 2026-10-10 | Replay answers unrecorded writes and unknown requests with exception 0x04, a warning and a counter. | Failing loudly in CI beats silently wrong values (VCR, WireMock and Hoverfly also default to errors); 01/02 would look like a wrong address map. |
| 2026-10-10 | Transport is hand-rolled asyncio MBAP/PDU framing; serve supports FC 3/4/6/16 and answers others with 01. | Fault injection needs per-request delay, silence, exceptions and disconnects; pymodbus hooks cannot do async delays or FIN cleanly and its internals change every minor release. |
| 2026-10-10 | pymodbus is a dev-only dependency (`>=3.15,<3.16`, no extras), used as the test "real device" and reference client; src never imports it. | Keeps the runtime independent of pymodbus releases; the `[development]` extra pulls in AGPL zuban. |
| 2026-10-10 | Recordings are JSON Lines v1: one header line, then one event per line, PDUs as lowercase hex. | Append-and-flush survives crashes, streams, and works with grep/jq and line diffs; YAML misreads hex and pcap needs GPL tooling or synthesized TCP. |
| 2026-10-10 | Device definitions and fault scenarios are YAML; duplicate keys and unknown keys are errors. | Hand-edited files need comments; PyYAML silently keeps the last duplicate key. |
| 2026-10-10 | Control API uses h11 with a small asyncio adapter on port 18502, bound to 127.0.0.1 by default (0.0.0.0 in the image). | One small MIT dependency, same event loop as the faults; 18502 is unassigned by IANA and outside ephemeral ranges; no auth, so loopback by default. |
| 2026-10-10 | Python `>=3.11`; CI tests 3.11 and 3.14; the image uses 3.14. | 3.10 is end-of-life; 3.15 waits for PyYAML cp315 wheels. |
| 2026-10-10 | Docker image: uv multi-stage build on `python:3.14-slim-trixie`, `uv sync --locked --no-dev --no-editable`, non-root uid 999, `ENTRYPOINT ["rigtape"]`. | Follows uv's official Docker guide; small image without dev tools; non-root by default. |
| 2026-10-12 | Modbus TCP is the first protocol; SCPI over TCP comes next. | A comparison of candidate protocols ranked it first on implementation effort and on fit with Docker and CI. |
| 2026-10-12 | Pin uv 0.13.0 in CI (setup-uv `version`) and in the Docker image. | The lockfile is made with uv 0.13.0; one uv version everywhere avoids lockfile drift. |
| 2026-10-12 | Pin the Docker base and uv images by tag and digest. | Reproducible builds; tags alone can move under the same name. |
| 2026-10-12 | Fault injection starts with four request-level faults: delay, no response, Modbus exception response and disconnect (FIN), with per-request matching (unit, function code, address), probability/after/count, fixed seeds and an HTTP toggle API. Byte- and connection-level faults (RST, jitter, late replies with old transaction ids, split frames, garbage bytes) are left out for now; they would be new rule types on the same engine. | These four are enough for the README walkthrough and for most timeout and retry tests; new fault types plug in as rule types without changing matching or seeding. |
| 2026-10-12 | License under Apache-2.0. | An explicit patent grant, which company legal teams tend to prefer; compatible with every current dependency. |
| 2026-10-12 | `serve` prints one JSON READY line on stdout once listening: `{"event": "ready", "modbus": {"host": ..., "port": ...}, "mode": "serve"}`; logs go to stderr. | Scripts, tests and the Docker smoke wait on it instead of the published port (docker-proxy accepts early); an object keeps IPv6 hosts unambiguous and is easy to read with jq. |
| 2026-10-12 | A ramped register must be read-only (an input register or `readonly: true`), and a ramp cannot move toward another ramped register. | A client write to a moving value and chained targets have no single obvious meaning; one rule keeps the reads deterministic. |
| 2026-10-12 | `source` is optional in device.yaml but required for files under `examples/` (checked by `tests/test_rules.py`). | The project rule is about shipped examples; users' own maps should not need it. |
| 2026-10-12 | Binding errors (port in use, permission denied, bad host) exit with code 2 and a hint. | They are fixed by changing arguments, like other usage errors. |
| 2026-10-12 | A ramp keeps its position unrounded and reads report the nearest whole count; a write to its target continues from that position. | Control software often rewrites the setpoint every cycle; restarting from a rounded value would slow or freeze the ramp, and rounding by direction would step backwards when the ramp turns around. |
| 2026-10-12 | Addresses, values and `readonly` are strict (no booleans or numeric strings); rates stay lax but must be finite. | A silently coerced `true` or `'10'` hides typos; YAML 1.1 reads `1e3` as text, so a strict rate would reject it; an infinite rate would crash every read. |
| 2026-10-12 | `examples/pid/client.py` is tested on Python 3.9 in CI (`RIGTAPE_CLIENT_PYTHON`), and ruff's FA rules run on it. | The README quick start promises stock python3 3.9+, e.g. macOS `/usr/bin/python3`; ruff alone does not catch 3.10+ runtime features. |
| 2026-10-13 | `rigtape record` never overwrites `-o`, keeps the request's arrival time as each exchange's `t`, stops *recording* an answer after a 30 s window (`timeout`) but never times the client out, and forwards late answers unrecorded with a warning. | Real-device recordings are hard to redo; replay sorts by request time; the proxy must stay transparent. |
| 2026-10-13 | `--source` is optional for users and required for recordings under `examples/` (checked by `tests/test_rules.py`); the READY line of record and replay carries `upstream`/`file` or `recording`. | Same rule as device maps; scripts can confirm what a process is doing. |
| 2026-10-13 | The pipelining and duplicate-TID record tests, and the record-then-replay round trip, use `rigtape serve` (with a fake clock) as the upstream, not pymodbus. | pymodbus 3.15's server answers only the first frame of a TCP segment, and a fake clock gives deterministic changing values; pymodbus interop stays covered by the byte-equality and file-structure tests. |
| 2026-10-14 | Replay drains a segment's remaining recorded responses for a write before treating that write as the next checkpoint; reads borrowed from a later segment take its first normal response. | A recorded failure followed by a successful retry of the same write must replay in order, and a transient 06 recorded right after a write must not become the pre-write answer. |
| 2026-10-14 | The recording header's `listen` is the bound address (written when the proxy starts listening), and `record` leaves no file behind when it cannot listen. | `--listen 0` would otherwise store `:0`; a header-only file would block the next run. |
| 2026-10-21 | Faults hook in through an Interceptor: `ModbusServer(..., interceptor=)` calls `decide()` once per request before the handler; a delay executes the request first and answers later, the other three faults skip the handler. | One request per connection in arrival order keeps a delayed request blocking the ones behind it, as a real device does. |
| 2026-10-21 | A rule's draw is `sha256(f"{seed}:{rule}:{n}")` for its n-th match, after `after` passes and while `count` remains; every matching active rule counts and spends, the first that fires wins. A missing seed is generated (8 hex chars) and printed. | Adding or removing rules never shifts another rule's pattern; the same seed reproduces a run on any machine or Python version. |
| 2026-10-21 | The control API starts only with `--faults` (default port 18502, `--api-port 0`, `--no-api`), has no bodies and no auth, warns when bound off loopback, and answers errors as JSON (404 with the rule names, 405, 413 over 64 KiB, 400, 408). Rule names are limited to `[A-Za-z0-9_.-]` so they fit in a path. | Without rules there is nothing to control; loopback by default keeps an unauthenticated API off the network. |
| 2026-10-21 | `match.address` overlaps the request's register range for function codes 1-6, 15 and 16; other function codes never match an address rule. | The engine must not parse every PDU; the address is at the same offset for these codes. |
| 2026-10-31 | The project is named rigtape (rig + tape): it says record and replay, and `rigtape serve`, `rigtape record` and `rigtape replay` read as sentences. File formats are `rigtape.device/v1`, `rigtape.faults/v1` and `rigtape.recording`; environment variables start with `RIGTAPE_`. | The name was not taken on PyPI, GitHub or Docker Hub, no product collisions were found, and it stays protocol-neutral when SCPI is added. |
